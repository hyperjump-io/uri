# What changed from v1

The API is the same shape, with the same names. These are the differences,
and why.

| Change | Breaking? | Why |
| --- | --- | --- |
| `toRelativeUri`/`toRelativeIri` take `(uri, base)` instead of `(base, uri)` | Yes, silently | Like `resolveUri(reference, base)` ([Resolving](resolving.md#torelativeiritarget-base)) |
| Parsers leave out components that aren't there, and return an ordinary object | Yes, for `in`, `Object.keys`, and deep equality | [Identifiers](identifiers.md#components) |
| Errors are classes with `value` and `rule` or `host` | No | [Errors](errors.md) |
| Messages say what's wrong and where, after v1's message | Only for code that compares a whole message | [Errors](errors.md#messages) |
| `authority` and `host` are optional in the types | Yes, for TypeScript | They aren't always there ([Types](types.md#optional-authority)) |
| Components are readonly in the types | Yes, for TypeScript | [Types](types.md#readonly-components) |
| An empty base authority is an authority | Fixes a bug | `file://` + `foo` was `file://foo` ([Resolving](resolving.md#the-bases-authority)) |
| Validators still throw for future IP literals | No | Now a decision, not an accident ([Future IP versions](future-ip-versions.md)) |

Designed, not implemented:

| Change | Breaking? | Why |
| --- | --- | --- |
| Scheme rules apply, and unknown schemes throw `UnknownSchemeError` | Yes | [Schemes](schemes.md) |
| Parsers don't validate, and `assert*` functions are new | Yes, silently for invalid input | [Trust](trust.md) |
| `resolve*`, `toAbsolute*`, and `toRelative*` don't normalize | Yes, silently | [Resolving](resolving.md) |
| `toRelativeIri` takes normalized identifiers | Yes, for TypeScript | [Resolving](resolving.md#torelativeiritarget-base) |
| The URI and IRI forms of `parse`, `resolve`, `toRelative`, and `toAbsolute` merge | Depends on the names | [Naming](naming.md#merged-functions) |
| Branded identifier types | Yes, for TypeScript | [Trust](trust.md) |

[Migrate from v1](../../website/migrate-from-v1.md) lists only the
deliberate breaking changes, not the rows marked "Fixes a bug". v1 can
still fix those bugs, and then what the guide said about v1 would be
wrong.
